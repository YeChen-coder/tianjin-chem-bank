# 迁移门槛与回退准备

当前只实现新内容存储和旧库只读适配入口；没有正式迁移、没有改旧库、没有切换旧服务。以下是可审阅的执行方案，不是已完成的迁移报告。

迁移前须完成同一真实整卷的导入→编辑保存→GLM 候选确认→导出→再导入对照；同时完成题号/选项/小问/答案目标、配图归属、原生公式与表格、全部页面视觉、旧功能回归。来源匹配先按文件摘要/题号/位置和内容相似度列清单；一对多、多对一、人工改题、不同版本或答案不一致的匹配全部保留待确认，不覆盖。

正式写入前用 SQLite backup API 制作一致性快照，记录原库摘要与记录数量、外部资产摘要、代码/依赖版本。增量迁移记录 old_id→new_id、来源摘要、旧分类/组卷引用、人工编辑标记、审核与 AI 历史版本；新结构写独立表，事务内核对版本。先小批代表材料、再审阅报告，不以导入题数作为正确性证据。切换前由用户审阅具体匹配/冲突/回退报告。

代码回退恢复上一份经过验证的 V2 代码/锁定依赖与配置，不覆盖别的会话尚未提交的文件。数据回退以一致性备份恢复旧库，在切换前后按时间戳保存 v2 content.sqlite、history、legacy_links、sources 和 assets；回退前另作一次当前库备份，保留切换后新教师编辑。新编辑可以导出结构化 JSON 与私有资产清单，等待冲突核对后重放，不能直接抹掉。

现阶段验证仅覆盖私有模拟库，原件及原库不用回退。没有生产匹配清单和最新正式备份，因此不执行正式迁移。

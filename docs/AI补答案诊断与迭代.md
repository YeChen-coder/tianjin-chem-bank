# AI 补答案诊断与迭代

## 本轮修复

审题结果的 JSON 能解析但小问列表缺失、为空或编号不合格时，在服务接替流程内检查格式，再尝试已配置的备用服务。两个服务都返回无效结构时仍停止，不编造题目或答案。

核对理由区分 AI 作答错误与未选中选项本身的错误；“无漏答”“无矛盾或漏答”不会因为含有疑点关键词而被降级。选错选项、实际作答或解析错误、条件不足、看不清图和漏答仍阻止自动确认。反向选择题可以说明被选选项“不正确”。

算式检查不把 `64/32=36/M` 或 `1+6=4+3` 截成不完整的数值等式；完整的数值算式算错仍提示核对。符号式与化学推理仍依赖独立审核，不能因为数值检查不报错就认定正确。

新导入时识别独立的答题卡说明、试卷题量说明和相对原子质量表，避免将说明中的序号和分隔线当成题目与答题空。旧库中已存在的这些记录在补答案前提示核对原文件，不发送模型请求。附在真实题目上的质量参考信息保留；不会删除旧记录或改试卷引用。

补答案提示版本更新为 `chem-answer-v3`，加强未知物与未知系数的原子守恒检查，要求使用九年级的质量守恒及比例解法。启动脚本兼容 `.venv\Scripts\python.exe` 和发行包自带的 `python\python.exe`。

## 维护循环

1. 在实际执行电脑确认项目、正式数据目录、服务进程、待处理任务和代码文件 SHA256；云电脑的 git HEAD 不能代替实际部署文件的核对。
2. 从已保存任务和小问记录取少量失败样本，区分非题目或残缺题、缺图、请求失败、真实答案分歧和程序误报。缺少原始模型返回时明确说明，不猜测模型实际输出。
3. 诊断包通过私有聊天附件或已授权的文件通道回传维护电脑，不放入公开代码仓库。只保存有关题目的最终响应和简短依据，不传密钥或全库。
4. 用旧响应离线复现规则误报，新增回归检查。离线重放只比较程序判定，不代表重新看图或重新审核科学性，也不写入正式答案。
5. 通过回归后交付明确的代码文件列表、文件哈希及 commit。接收方备份旧代码，逐文件复制并校验，不覆盖题库、图片、导入文件或密钥。
6. 在原执行电脑核对服务与题量，先做几道同题验收并回传结果，再按实际结果决定下一轮。残缺题需要检查原文档，不能靠重复补答案替代修复导入。

本轮本地真实记录重放中，七道因关键词或截断算式而被降级的题通过了原有三次作答及审核记录的程序判定；另识别了四十七条试卷说明。其他科学错误、图片不足及残缺设问不以规则修复为由自动放行。正式数据中的既有答案不因升级自动修改。

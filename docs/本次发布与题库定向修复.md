1. 拉取指定发布commit到Grok云电脑，核对commit、代码及依赖，在独立临时数据目录运行离线测试。不能把云电脑的测试库或旧库当作妈妈正式库。
2. 确认妈妈电脑上的实际程序目录、实际CHEM_DATA_DIR、现有端口和数据库身份。记录题量、试卷/引用、手工修正和待确认答案的基线。
3. 在任何程序启动迁移、覆盖或数据修复之前，先停相关程序与AI写入，确认停止；用SQLite backup API创建一致的数据库备份（或确认所有连接已关闭后备份）。在妈妈电脑的独立备份目录保留数据库、完整media含original、源imports、已有导出、启动脚本和keys.local等配置；敏感配置只留本机，不发消息或GitHub。备份附文件清单/哈希、PRAGMA integrity_check、恢复方法和旧程序版本；已有文件不覆盖。先验证能在独立恢复副本打开。
4. 云电脑验收通过后才同步程序到妈妈电脑。保留妈妈电脑的密钥、数据和环境路径，只补充缺失配置，不拿Harvey或云电脑配置覆盖。第一次维护启动设CHEM_DISABLE_AI=1，避免恢复任务或消耗API。
5. 修复先在妈妈电脑备份的独立工作副本上进行，产出逐题变更清单、前后字段和源证据。校验通过后才以短事务定向应用到正式库。保留正式题号、已有试卷及顺序、题目来源和教师编辑；不全库清洗或重新导入。
6. 已有教师修改与修复不一致时保留修改并记录冲突，不凭模型覆写。题型人工锁、题干锁、答案记录revision/stem_hash、rich answer metadata须一致；不能只UPDATE questions.answer而让页面/导出仍读旧候选或结构化答案。可采用现有编辑接口/保存逻辑完成一致更新。
7. 程序与数据库分开验收、可分别回滚。检查新程序commit、题量/试卷/外键、图片完整性、目标题页面和附答案Word导出；不要新发起AI任务。保留原卷、benchmark、raw-results和已有模型记录作为证据，不合并它们的bank.sqlite。

## 1. 用最简单的话说明要做什么

用户导入一套 Word 试卷，程序把题目分好，把文字、公式、图片、表格整理好。用户可以直接编辑、保存，也可以让 GLM 改写，再导出为规整、可编辑的 Word。

四步流程：

**导入并分题 → 卡片展示与编辑 → GLM 改写 → Word 导出。**

公式统一用 LaTeX 表达。普通文字、表格和配图保持各自的结构，不把整篇试卷改成 LaTeX 文档。

重构重点是让四步共享一套题目内容结构，不必推倒现有分类、检索、组卷、人工审核和版本管理。现有功能需要回归验证。

## 2. 范围与约定

- 输入：原始 `.doc`、`.docx`，优先从用户提供的原文件重新解析。PDF 暂不纳入。
- 界面：暂定网页程序；教师不用学习 LaTeX，不要求安装公式编辑器。
- AI：以用户当前使用的 GLM 为主要接入与验收对象；保留现有其他服务能力，不以其他模型的测试代替 GLM 验收。
- 输出：可继续编辑的 Word。公式应为 Word 原生公式，表格应为 Word 表格。
- 数据：保留题目分类、组卷引用、来源信息及人工修改。原文件只读，转换处理副本。
- 排版目标：内容完整、结构正确、清楚规整。网页与 Word 可以合理地换行不同，不追求逐像素复刻原卷。
- 未确认的图片识别结果、未知符号和不支持的结构必须可见、可核对；不能悄悄删除或根据题意猜测。
- 本文中的新数据结构、GLM 协议、迁移流程均为设计建议。当前仅编写方案，未恢复开发或批量处理题库。

## 3. 第一步：导入与分题

### 用户需要得到什么

| 编号 | 需求 |
| --- | --- |
| I1 | 接收 DOC/DOCX，显示进度、来源和处理结果；失败时说明原因 |
| I2 | 区分试卷说明、大题栏目、独立题目、题内小问；保留原顺序和原题号 |
| I3 | 同一道大题内的小问保持层级，允许用户明确拆分；不能默认全部拆散 |
| I4 | 表格、配图、公式跟随所属题干、选项或小问；跨段、跨页内容不能被截断 |
| I5 | 识别参考答案区域并建立对应关系；不确定的答案归属进入核对清单 |
| I6 | 导入后提供真实整卷预览与题目列表；支持修正分题边界、合并和拆分 |
| I7 | 重复导入同一输入版本应复用结果或提示已有版本，不能覆盖人工编辑稿 |

### 技术路线

1. 保存原文件摘要与副本。DOC 通过隔离的转换步骤生成 DOCX；检查包内有真实的 `word/document.xml`，不能只看扩展名或 ZIP 判断。
2. 先读取 Word 结构：段落、文本 run、编号、表格、图片关系、上下标、原生公式、旧公式对象、字段及特殊字体编码。
3. 根据题号、编号层级、栏目和答案区域分题。分题与公式转换分别处理，但都引用同一份原始结构，避免先扁平化丢信息。
4. 按公式来源选择恢复路径；再形成统一题目模型。原文件位置和转换状态记录在模型中。
5. 汇总题目数、公式数、配图数、待核对项。用户能定位到具体题目和原文位置。

公式恢复优先级：

| 来源 | 路线 | 失败处理 |
| --- | --- | --- |
| Word 原生公式 OMML | 结构读取 → MathML → LaTeX | 保留原结构及原显示，标记不支持项 |
| MathType / 旧编辑器对象 | OLE/MTEF → MathML → LaTeX | 保留对象与预览图，不直接跳过 |
| 旧 EQ 字段、嵌入原生结构 | 已验证的字段/结构解析 → LaTeX | 保留指令与缓存结果，进入核对 |
| 字体符号、普通文字上下标 | 编码映射、脚标属性与公式边界解析 | 原编码保留；不凭题意推断关系符号 |
| 文字＋关系/条件图片 | 确认条件与左右边界后合成完整公式 | 证据不足则保持原内容并给出候选 |
| 真正只有图片的公式 | 本地识别 → LaTeX 候选 → 核对确认 | 保留原图，识别失败不冒充已转换 |

不能将“扣除单位后剩余英文”作为主要公式识别算法。选项字母、变量、名称缩写、pH 等会混淆。普通用量如 `50 mL` 可以是文字；完整计算式中的单位可以随算式处理。

### 验收

用真实整卷逐题对照：题目及小问顺序、选项、答案对应、正文、公式、表格与配图归属正确。无法处理的内容全部保留并列入清单。候选题目数量正确不能单独证明分题正确。

## 4. 第二步：卡片展示、编辑与保存

### 用户需要得到什么

| 编号 | 需求 |
| --- | --- |
| E1 | 卡片及整卷预览共用显示逻辑；公式上下标、电荷、反应条件清晰 |
| E2 | 点击公式进行可视化编辑，提供常用下标、上标、分数、箭头和条件模板；LaTeX 源码入口可作为高级功能 |
| E3 | 修改文字不损坏旁边的公式；编辑公式不改变选区之外的文字 |
| E4 | 图片支持选项内、题干内、小问前后及独立段落放置；可调尺寸、对齐，保持比例 |
| E5 | 表格支持单元格里的文字、公式、图片，以及必要的行列、合并关系和列宽编辑 |
| E6 | 取消不改变已保存内容；刷新、重复导入及服务重启后保留修改；提供撤销或版本恢复 |
| E7 | 保存中断、重复提交、编辑冲突不能静默覆盖内容；明确显示保存结果 |
| E8 | 常用桌面与 390px 手机宽度可阅读；长公式或宽表格有明确的换行/滚动策略，避免整个页面溢出 |

### 技术路线

- KaTeX 负责显示，MathLive 负责编辑；使用固定版本的本地资源。当前试验版本是 KaTeX 0.16.22、MathLive 0.111.1，不在重构中未经测试自动升级。
- 短公式以行内形式跟随文字；长公式使用独立段落。公式内部由工具排版；字号、行距、段落与分页规则由网页/导出模块安排。
- 保存的是结构化题目，而非拼接 HTML。普通编辑器不能把公式压成无结构字符串。
- 图片位置记录为“属于哪个内容块、放在什么顺序”，尺寸保留物理单位/比例。原 Word 浮动图片需要结合锚点与预览核对；不能只读取 ZIP 内媒体顺序。
- 合并单元格、嵌套或特别复杂的表格必须检查支持范围。暂不支持的结构保留并提示，不压成普通文字假装成功。
- 公式编辑提交完整 LaTeX，服务端编译并检查后更新；保留原结构与转换来源。未修改的原生公式可复用验证后的 OMML，不反复有损转换。
- 所有编辑以题目版本及内容节点 ID 定位；异步结果与所属文档、目标公式、编辑会话绑定。

### 验收

教师不写代码即可修改公式和图片位置。测试文字、公式、表格、答案混合编辑及取消、刷新、重启、冲突；源内容与选区外内容保留。新用户操作顺手程度必须单独验收，不能用编译成功代替。

## 5. 第三步：GLM 改写

### 用户需要得到什么

| 编号 | 需求 |
| --- | --- |
| A1 | 继续使用主用 GLM；保留已有改写强度、教师意见、版本与审核流程 |
| A2 | 请求携带完整上下文：题干、选项、小问、表格、LaTeX 公式及必要配图 |
| A3 | 返回的题干、选项、答案、解析都支持公式；新增公式应可编辑、可导出 |
| A4 | 变式作为独立候选版本保存，不能直接覆盖母题或已确认答案 |
| A5 | 明确区分格式通过、内容核对通过和教师确认；格式成功不等于答案正确 |
| A6 | 配图复用必须适合新题，不能改了题干却继续引用不相符的装置图 |
| A7 | 请求失败、截断、格式错误和取消均有明确状态；重试有上限，旧响应不能覆盖新版本 |

### 技术路线

使用显式内容类型的 JSON 协议，让 GLM 返回“文字、公式、图片引用、表格”，公式使用独立 LaTeX 字段。发送时也使用同一结构，并提供易理解的格式示例。

LaTeX 是文本，可以通过 API 传输；不需要为了发送给 AI 把已恢复的公式重新截图。依赖装置图等图像信息时，须使用实际配置中支持图像输入的模型；不能假定每个 GLM 型号都能看图。

后端依次检查：

1. JSON 完整，字段与类型符合协议；保留真正的公式反斜杠，避免 JSON 转义损坏。
2. 题干、选项、小问、表格以及答案/解析内容完整；图片引用限于当前允许使用的资产。
3. 公式能够在网页显示并转成 Word；不支持的命令不能悄悄删掉。
4. 内容核对：题目条件、各小问、答案、解析与配图一致；沿用现有独立核对及教师确认机制。

不合格结果保存为失败/待修候选或执行有限重试。不得通过自动猜数字、关系符号、反应条件来“修复”题意。历史纯文本输出可做保守兼容识别，有歧义则人工确认。

现有 `aivariant.py` 已有 GLM JSON 请求基础，但候选清理主要支持 text/img；题目画像与父题请求也主要使用字符串。需要同步修改请求、返回清理、候选保存、核对请求、前端展示和导出。`aianswers.py` 的答案/解析路径同样需要升级。

GLM 官方结构化输出资料：<https://docs.z.ai/guides/capabilities/struct-output>。JSON 模式不能替代本地类型、公式与内容检查；具体接口和当前配置型号仍以实际测试为准。

### 验收

用当前主用 GLM 对真实样本测试完整往返，记录请求模型、协议版本、返回状态及人工核对结论。至少覆盖普通化学式、离子电荷、带条件反应式、pH 比较、计算式、表格题、配图题，以及答案/解析中的公式。还要覆盖错误响应和取消。

开发时先用固定模拟响应验证格式错误、截断和结构保留，再做受控的真实 GLM 测试。记录测试调用数量/用量，不把凭据写入日志；此方案编写过程中未调用 GLM API。

## 6. 第四步：Word 导出

### 用户需要得到什么

| 编号 | 需求 |
| --- | --- |
| W1 | 导出原题、人工修改题、AI 候选确认题时，统一使用当前保存的内容版本 |
| W2 | 公式为 Word 原生可编辑公式；普通文字、表格保持可编辑；普通配图保持原图质量 |
| W3 | 上下标、电荷、条件、箭头、正体字母和括号组正确，无缺字或异常占位符 |
| W4 | 图片与对应题干、选项、小问同属正确内容，尺寸和对齐规则有效 |
| W5 | 长题、表格与公式分页规整，避免题号孤立、短选项被拆散或内容重叠 |
| W6 | 未解决的公式不能无提示冒充成功导出；保留原显示的降级导出须列出未转换项 |

### 技术路线

题目模型 → Word 段落/表格/配图；公式走 **LaTeX → MathML → OMML**。已确认未变的原生公式可保留原 OMML。编译结果按 LaTeX、转换器版本和相关配置缓存，修改后不得使用旧缓存。

使用实验中验证过的完整性检查与必要结构修复。不采用“公式截图作为正常导出结果”。图片资产保留原文件，网页预览缩略图不作为默认 Word 画质来源。

网页和 Word 共用内容与排版意图，但各用自己的排版引擎。分页需要单独规则和实际 Word 检查；不承诺任意大小表格都能放在一页。

**部署前必须解决转换依赖：** 当前验证路径部分依赖开发机 Office 的转换 XSL，Word 视觉验收也依赖本机 Office。不能以本机能运行推断普通服务器可直接部署，也不把 Office 文件直接打包分发。跨平台方案需选择可分发的转换实现并验收支持范围；当前 `formula_engine` 的备用转换只覆盖有限结构。线上路径与开发机 Word 验收工具分开。

### 验收

独立检查 DOCX 内公式、图片、表格及顺序；实际用 Word 打开、点击编辑公式、渲染全卷并逐页查看。包含一次网页修改后导出再导入的往返测试，确认内容和公式结构保留。

## 7. 四步共享的内容结构

下面概述目标模型。四会话开发共同遵循 [接口约定 v1](docs/word-latex/PARALLEL_CONTRACT.md)，具体字段以该文档为准；这些接口尚未实现。

```text
题目：ID、版本、来源、原题号、题型、分类
  题干内容块：段落、表格、独立配图
    段落内部：文字、公式、行内图片
    表格内部：行、列、单元格内容、合并关系、列宽
  选项：各选项自己的内容块
  小问：编号、自己的内容块、作答位置
  答案与解析：内容块及与小问/作答位置的关联
  原始内容、人工编辑/AI 版本、待核对事项
```

公式至少记录：稳定 ID、LaTeX、原始来源及原结构/原图引用、转换状态、转换器版本。MathML/OMML 是可验证的转换结果，不作为另一份独立编辑真相；修改后必须更新或失效。

图片至少记录：资产 ID/摘要、原始文件与预览、尺寸/比例、所属内容块、行内/独立放置及对齐。AI 引用资产 ID，不能发明任意图片地址。

每个内容块保留稳定 ID 与来源定位。内容版本与渲染缓存分开；显示规范化不能改题目身份、去重键或教师已确认答案。节点状态可为已恢复、识别候选、已确认、未支持，界面使用简单中文呈现。

新增 `schema_version`，旧数据经兼容适配器读取。公式请求与返回、编辑保存均有版本检查，避免冲突覆盖。缓存只负责加速，不能成为用户编辑结果的唯一存储。

## 8. 原文件与旧题库的迁移

1. 备份数据库、媒体与必要配置，保留版本收据。已有备份不能替代正式切换前的最新备份。
2. 从原 Word 副本建立新解析结果，在独立存储中核对整卷，不直接覆盖旧题库。
3. 建立来源文件版本、原题号及内容位置的匹配关系，辅以文本/图片摘要；存在重复或不确定匹配时列出冲突，不能强行对号。
4. 将旧分类、组卷引用、人工题干/答案/配图修改和 AI 历史关联到正确题目。人工编辑不是可被重新导入随便替换的缓存。
5. 给出迁移报告：已匹配、冲突、未匹配、公式候选、未支持项；用户能看整卷和改动对照。
6. 通过兼容层逐步切换导入、展示、人工编辑、GLM、导出。批量任务支持断点继续、幂等与失败重试；回滚方案覆盖代码、数据库和新写入版本的保留。

目前根题库只读检查为 10,264 道题，旧题目 segments 未发现保存的 OMML。说明旧数据不足以替代原文件，不意味着原文件没有公式结构。

## 9. 实验中遇到的坑：简洁经验表

| 坑 | 实际处理与后续要求 |
| --- | --- |
| 把旧公式的预览图当成唯一来源 | 优先恢复 OLE/MTEF 或原生结构；纯图片才走识别 |
| 开源转换器不是原样就全部通过 | 针对括号验证等补适配；39/39 是适配后样本结果，不是任意 Word 的准确率 |
| OCR 输出很像正确公式，但字符错了 | 实测有 Fe → FΘ、Cu 误读；保留原图核对。模型概率不能当正确率 |
| 下标只挂在最后一个字符/括号上 | 保留完整括号组、离子整体和脚标结构，不靠扁平字符串重建 |
| 温度、双下划线、加热符号变成歪斜文字 | 依据明确的源结构恢复条件；260℃、900℃在关系符号上方。不要按题号硬编码 |
| 编辑器导出的 MathML 丢掉向量底数等 | 保存完整 LaTeX并服务端重新编译；不把编辑器序列化当唯一 Word 来源 |
| 空底数上标、摄氏度、装饰在 Word 中变样 | 使用验证过的局部修复并独立检查结构；不能只检查字符数量 |
| 删除整个 Word run 时误删公式两边文字 | 仅替换目标对象，保留同 run 前后文字及顺序 |
| 旧 DOC 有嵌入 ZIP，或旧 XML 命名空间残留 | 检查真正 DOCX 内容；重建正确命名空间，并实际打开 Word 验证 |
| 取消后旧转换结果写进另一条公式 | 绑定文档、公式 ID 与编辑会话；丢弃过期响应，保存有版本检查 |
| 浏览器选区偏移，改错文字范围 | 按文档字符定位并处理 UTF-16 差异，不按屏幕像素猜位置 |
| 图片位置对，但继承了错误对齐/尺寸 | 独立图片使用自己的段落规则，保存物理尺寸；核对小问与选项内顺序 |
| 网页好看，但 Word 出现断行、分页问题 | 网页和 Word 分别验收；短表格行和题干开头设置分页规则，长内容允许合理跨页 |
| ZIP 里废弃旧公式预览被误报为丢图 | 核对实际引用的配图，不把未引用旧媒体算成应展示内容 |
| 测试改坏用户验收稿 | 使用私有测试数据目录，测试前后核对原件与编辑稿；新批量任务同样隔离 |
| 只做前端公式显示，AI/保存仍丢结构 | 四步共用模型，答案和解析也接入；不能只升级题干显示 |

表格合并、各种浮动图归属、大量新原文件的分题以及 GLM 新协议，仍是待验证范围，不列为已解决经验。

## 11. 四个会话怎样并行，怎样接起来

### 11.1 分工与唯一负责人

| 会话 | 对用户负责的部分 | 可以立刻独立做的工作 | 需要别人的交付 |
| --- | --- | --- | --- |
| 1：导入 | DOC/DOCX 结构恢复、分题、小问与答案归属 | 原文件解析、旧对象恢复、分题样本、导入报告 | 会话 4 的公共模型验证器/编译桥；未就绪时按接口注入替身 |
| 2：展示编辑 | 卡片、整卷、公式/图片/表格编辑 | 用共同样例和模拟 API 做完整界面、保存/取消/冲突测试 | 会话 1 的真实数据；会话 4 的保存与编译接口；会话 3 的候选内容 |
| 3：GLM | 改写请求、返回解析、答案解析与内容核对 | 用共同样例及固定模拟响应开发；配置可用后受控实测 GLM | 会话 1/2 的真实已保存题目；会话 4 的模型验证/公式编译与版本存储桥 |
| 4：导出与集成 | 原生 Word、共享底层、主程序接线、迁移与回归 | 用共同样例开发导出；建立公共模型/编译接口、mock 服务与保存桥 | 其余三个会话的模块及验收结果，供逐段联调 |

没有额外要求开第五个会话。会话 4 兼任集成负责人，先交付最小公共接口，再继续导出与整合；其余会话用同一份契约和替身推进，不必等待它完成全部工作。

共享文件只能由一个负责人修改：V2 中的主程序入口 `app.py`、数据库/导出入口 `banklib.py`、`document_display.py`、公共内容模型、`formula_engine/` 和依赖由会话 4 管理。会话 1 拥有 V2 中的 `docx_import.py` 与新增导入目录；会话 2 拥有新增前端目录；会话 3 拥有 V2 中的 `aivariant.py`、`aianswers.py` 与新增 AI 目录。所有可修改路径相对于 V2，不是旧目录。详细路径见任务书。

其他会话需要改共享文件时提交接入清单或补丁建议，由负责人实际合并。不得各自修改一遍主程序入口，最后再靠手工解决大面积冲突。

### 11.2 先统一什么

共同接口 v1 明确：题目/内容节点 ID、版本、文字/公式/图片/表格格式、答案与小问关联、图片资产引用、编译与保存结果、错误和取消状态。四个会话不能自行发明另一套 `segments` 或公式字段。

会话 4 在开发启动时提供：公共模型校验、最小固定样例、编译服务适配接口及隔离的测试 API。样例来自现有已验证材料或明确标记的合成控制，不先等待全部原文件。

变更协议时由提出者写清原因、受影响字段/调用方和兼容办法；会话 4 更新契约及样例，再让受影响会话同步。不能只在某个会话的聊天里口头改接口。

### 11.3 真正的时间顺序

| 里程碑 | 可以同时推进 | 必须满足的衔接条件 |
| --- | --- | --- |
| M0：共同起点 | 盘点原件、研究各自模块、准备测试 | 共同代码基线与接口 v1 可读取；各自数据/端口隔离 |
| M1：四路开发 | 导入解析、模拟数据编辑、GLM 格式处理、固定样例导出并行 | 各自产物通过契约检查，能独立演示；不要求其他模块全部完成 |
| M2：逐段联调 | 已完成的两段先接，其余仍独立开发 | 导入输出 → 编辑；保存结果 → 导出；GLM 候选 → 编辑/导出。每个连接用同一份内容版本 |
| M3：全链路验收 | 回归、性能与异常路径检查可并行 | 同一真实 Word 经导入、编辑、GLM 改写、导出后，文字/公式/配图/表格及答案核对通过 |
| M4：旧库迁移与切换 | 会话 1 做来源匹配分析，其余修复发现的问题 | 会话 4 单独执行正式数据写入与切换；有最新备份、冲突报告及回退方案 |

依赖的是具体接口与产物，不是某个会话必须先结束。Word 导出可以用固定样例先做；只有真实全链路验收和正式题库切换需要等待相关模块达到交付条件。

### 11.4 如何避免相互干扰

- 四个会话共同使用指定 V2 作为项目根目录，按文件所有权并行开发。测试数据库、缓存、编辑稿、队列及输出分别放入 `.work/session-1` 至 `.work/session-4`，不得共享写入。新虚拟环境由会话 4 单独创建和维护，不能搬旧 `.venv`。
- **旧工作区有大量未提交、未跟踪、被忽略的实验文件。** 不整份照搬，也不各自从旧 HEAD 猜基线。会话 4 维护 V2 的复制清单与必要公共基线；各模块负责人只按需复制自己负责的文件并登记来源摘要，公共资源只有会话 4 复制/更新，避免相互覆盖。
- 测试端口建议分别用 8901/8902/8903/8904，先检查占用。不得复用或重启用户验收服务 8893；8894 也是已有私有试验服务，不默认接管。
- 原始 Word 可以共享只读访问，数据库和编辑稿不能共享写入。测试不得写根题库或重置其他会话修改。
- Word 自动化渲染由会话 4 顺序执行；其他会话提交待验证文件，避免多个隐藏 Word 任务相互影响。
- GLM 真实测试以会话 3 为执行者，使用私有任务队列；集成测试调用前统一安排，避免重复后台调用。其他会话默认使用模拟结果。
- 合并由会话 4 做，先在集成副本验证，保留所有原有未提交修改。单会话功能通过不等于正式系统已经切换。

### 11.5 用户怎么控制进度

每个会话维护自己目录中的 `STATUS.md`，固定报告：所属会话、共同基线、接口版本、已完成、验证证据、未完成、依赖项、可交付文件/提交，以及是否写过正式数据。

状态使用：未开始 / 独立开发中 / 可以联调 / 联调通过 / 待用户查看。遇到接口依赖时写具体字段或产物，并继续可独立完成的工作，不笼统声称“等上一个做完”。

你可以让每个会话回答：“按照任务书更新 STATUS.md，用三句话告诉我完成了什么、还缺什么、能不能交给集成。”然后让会话 4 汇总四份状态。查看其他会话产物不要求自动发送消息；跨会话发消息仍需用户授权。

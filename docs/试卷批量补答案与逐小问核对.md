# 试卷批量补答案与逐小问核对

本功能给已经选进某套试卷的原题补答案，与“AI改写”分开。原题、题号、图片和试卷引用保持原样。

## 老师如何使用

1. 打开已经保存的试卷，点击“AI批量补答案”。整套试卷中没有答案的题会进入等待；已有文字答案、图片答案和已有待确认结果跳过。
2. 每题下方显示读题、第一次作答、第二次独立作答、第三次独立作答、逐小问核对的进度。结果自动保存、自动更新，不必重复点击。
3. 展开“答案 / 解析”。每个小问分别显示“独立核对已通过”或“存疑”。存疑位置保留三次可能答案和简短依据；其中有请求失败时保留实际得到的结果，并说明独立核对未完成。
4. 已通过的答案可以直接改，停下输入后自动保存。存疑小问可以填写、修改，或点“填入这一答案”；此时保存的是待确认草稿。老师核对后点击“确认这一小问”，才保存为正式答案。其他已确认小问保留。
5. “重新核对待确认的答案”可以再次尝试。已有确认结果保留，不会因为重试全部覆盖。仍没有完整核对结果时继续存疑。
6. “叫停所有当前AI生成”同时叫停改题和补答案；已经保存的结果保留。正在请求的结果即使稍后返回，也不会重新写入。

答案属于题库里的这道题，所有引用这道题的试卷共同使用。手动补答案也支持自动保存；两个窗口同时编辑时，旧输入不会覆盖已经保存的新答案，页面保留当前输入供老师处理。

导出默认不带答案。勾选附带答案后，按小问导出确认结果；未确认的位置写明“答案存疑，待教师确认”。三次可能答案和待确认草稿留在题库页面，不作为正式答案导出。

## 如何独立核对

先列出需要作答的位置。连着的简答问句逐问拆分；适用的填空、实验题按原题的空位拆分，两个连接顺序的空分别保存。

随后发起三个独立请求。每次只看原题、原图及作答位置，不看到其他次的答案，也不从题库旧答案取结论。文字题使用不同层级模型；带图题所有步骤均使用能接收原图的模型。两家密钥可用时，第二次作答和最后的核对优先使用 DeepSeek，其他步骤优先 GLM。服务失败仍可以接替，GLM 已确认额度不足时暂停尝试十分钟。

最后一个独立核对请求逐小问检查三次答案及其解析、条件、图像事实、计算和必答要点，并分别记录每次是否正确、是否等价，以及经过检查的答案和简要解析。只在三次完整作答均可用、等价且审核通过时写入正式答案。不以多数票消除不同的实质答案；等价措辞、合法开放性例子和化学式排版不要求逐字相同。

另有保守检查防止审核自相矛盾：选择题核对字母集合；明确的数值结果比较单位换算后的数值；简单的显式算式重算；常见固态产物被误标为逸出气体时拦截；“使用的发生装置”与连接顺序起点矛盾时标记相关小问。这些检查不能覆盖所有化学错误，审核模型也可能误判，教师仍须作最终把关。

如果检查发现漏列小问，会另列待确认位置。能够定位的疑点只作用于相应小问；若无法确定漏答在哪里，整题暂不自动确认，以免遗漏被误当成已完成。

## 保存和升级

升级新增 `answer_records` 和 `answer_jobs`。前者保存题目绑定的各小问状态、答案、草稿、三次候选及独立审核证据；后者保存后台任务和原题快照。只有确认结果写入原有 `questions.answer`，因此既有搜索和引用继续能使用答案。密钥不写入表、报告或页面。

老师修改题干后，旧答案的自动核对标记失效，导出不会把旧核对结果当成新题的确认答案。生成途中修改题干或答案时，后台停止继续处理，或在写入前发现版本变化而丢弃结果，保留老师的修改。程序重启可重新处理被中断的任务，仍使用上述变化检查。

原题库不会全量重写，不自动补齐几千道题；只处理老师在试卷里明确发起的任务。开发和真实接口测试均使用 `.dev` 的独立题库与现有虚拟环境，没有修改正式题库、原始 Word 或密钥文件，也没有把这些文件提交到 GitHub。

## 2026-10-07 验证记录

使用本机现有密钥分别跑了 GLM 和 DeepSeek 的六种题型。随后按实际的双服务配置再次跑完六种题型：单选、多选、填空、简答、带图实验、计算。每题正常流程包含读题拆分、三次独立作答与审核，不能用一次普通聊天的耗时估算。以下是双服务这轮真实调用的耗时；确认数量使用最终校验规则重新检查真实响应后的结果，不是增加调用次数挑选成功答案。

| 题型 | 耗时 | 独立小问 | 自动确认 | 存疑 |
| --- | ---: | ---: | ---: | ---: |
| 单选 | 11.57 秒 | 1 | 1 | 0 |
| 多选 | 19.18 秒 | 1 | 1 | 0 |
| 填空 | 20.54 秒 | 6 | 6 | 0 |
| 简答 | 33.22 秒 | 5 | 5 | 0 |
| 带图实验 | 54.01 秒 | 7 | 4 | 3 |
| 计算 | 29.29 秒 | 3 | 1 | 2 |

实验样本有题干装置字母与连接顺序矛盾，相关三个空保留可能答案，其他四个小问保存。计算样本出现同一小问答案写 3.2g、解析又算 1.6g，以及某次把二氧化锰标成气体；这些问题在最终规则中分别拦截，不影响另一个通过的小问。测试发现审核模型有时会只看解析里的正确数值而忽略答案字段的矛盾，因此增加上述数值和式子检查。接口 HTTP 成功不等于答案通过。

另模拟 GLM 返回余额不足代码 `1113`，后续读图、作答和审核真实调用 DeepSeek。只触发一次模拟 GLM 失败，整题完成约 11.76 秒，四问确认、三问因原题矛盾存疑。此测试模拟故障，没有消耗实际余额制造不足。

最终真实响应经当前校验规则重放，并核对确认答案写入、存疑候选留存、默认学生卷省略答案、附答案卷按题附加确认结果及待确认标记。导出检查针对 DOCX XML 与文件结构，没有声称完成 Word 页面渲染验收。本轮没有重新请求已被拒绝的浏览器访问。

自动回归覆盖只处理缺答案题、图片答案保护、独立请求不互相参考、语义等价、逐小问分歧、审核/作答失败、草稿保存与教师确认、编辑冲突、题干变化、生成期间教师编辑、删除与叫停、重试保留教师答案、接口停用及两种导出。另验证 Python 和页面脚本语法。

最终 `python -m pytest -q`：90 项通过；独立的 `python test_aivariant.py` 也通过。发布检查确认 README 原文前缀和 NOTE 保留，六个受保护的正式数据文件哈希不变，提交文件不含本机密钥。

## 给维护者的接口

- `POST /api/papers/<id>/ai-answers`：给整套试卷缺答案题排队；返回 `jobs` 和 `skipped`。
- `POST /api/questions/<id>/ai-answer`：单题作答或重新核对，传 `paper_id`；题目必须在该试卷中。
- `GET /api/papers/<id>/answers`：整卷状态及 `active`。
- `GET /api/questions/<id>/answer`：题目绑定的答案、小问、候选、任务状态和编辑版本。
- `POST /api/questions/<id>/answer`：传 `revision`、`answer`；编辑小问再传 `part_id`，教师确认传 `confirm: true`。过期版本返回 HTTP 409，不覆盖现有答案。
- `POST /api/ai/stop-all`：同时停止改题和补答案。

正常启动程序会补齐新增表，无需重新导入旧 Word。使用新版代码后重启程序并刷新页面即可。

## 先给用户看的说明

我们正在做一个“整理 Word 题目里的公式”的工具。

目标是：原来的上下标、特殊符号、反应条件等，变成能编辑的公式；网站上排版整齐，导出 Word 后也能继续编辑。

已经决定以 **LaTeX 作为公式的统一表达方式**。不是把整张试卷、题干和配图都改成 LaTeX。

流程是：

**原始 Word → 找出并恢复公式 → 统一成 LaTeX → 网站显示和编辑 → 转回 Word 原生公式。**

不同来源的处理：

| 原文件里的内容 | 怎么处理 |
| --- | --- |
| Word 原生公式 | 尽量读取原来的结构，再转成 LaTeX |
| 旧公式编辑器 / MathType 对象 | 提取对象内部结构，不只处理它的预览图片 |
| 普通文字里的上下标、特殊字体符号 | 根据文字、字体编码和上下标属性恢复 |
| 一半文字、一半公式图片 | 在能确认边界与内容时合成一个完整公式 |
| 只有图片的公式 | 识别出候选公式，再核对；不能保证自动识别全对 |
| 装置图、示意图、曲线图 | 继续保留图片，整理它与题干、选项、小问的位置 |

现在完成的是独立试验，已经有真实整卷可以看。主项目还没有完成这条流程的接入，也没有把全部旧题库转换完。

## 后续方案讨论：AI 改写与公式往返

用户提出四步流程：导入分题 → 整理公式/表格/图片并展示卡片 → 人工编辑与 AI 改写 → Word 导出。整体方向成立，但应保留大题与小问层级，不把所有小问强行拆成独立题目。先读 Word 结构，再据题号与层级分题，避免配图、表格、公式归属丢失。

以下是讨论中的设计建议，尚未实现或通过 GLM/DeepSeek 的公式端到端实测；开发仍暂停：

- 用统一题目结构保存文字、公式、图片引用、表格及小问关系。导入、人工编辑、AI 输出、网页显示、Word 导出共用这套结构。
- AI 请求中显式携带 LaTeX 公式和前后题干、选项、小问、表格及必要配图，不只发送旧的扁平 body 或题目画像。LaTeX 本来是文本，可以传输；模型是否正确理解仍需真实样本测试。
- 约定 AI 返回带类型的内容块：普通文字、公式（LaTeX 字段）、图片引用、表格。程序按类型处理，避免从所有英文字符猜公式。正文、选项、答案、解析全部采用同一约定。
- 返回后检查结构、允许的图片引用和公式是否能显示/转换；失败时保留候选供修正或有限重试。公式排得出来不代表化学内容正确，原有答案/内容核对仍须保留。
- “排除常见单位后把剩余英文都转公式”不能作为主要规则：选项 A/B、变量、pH、名称缩写可能混淆，pH>7 还含数字和关系符号。普通独立用量如 50 mL 可留在文字；完整算式里的单位可随算式一起处理。旧纯文本输出仅以保守识别作为兼容路径，有歧义不自动转换。
- 复杂有机结构图或新题需要新装置图时，不能以支持 LaTeX 为理由假定已支持；配图复用要检查它仍符合新题。

现有代码证据：`aivariant.py` 的 `build_variant_segments` 只接受 text/img；`_profile_user` 主要发送 body、answer、图片信息；`_generation_user` 的父题内容目前也主要是字符串。`aianswers.py` 的答案/解析记录同样需要同步支持公式。现有 JSON 请求机制可复用，但 JSON 格式正确不等于公式结构或题意正确。

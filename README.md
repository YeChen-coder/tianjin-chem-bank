# 天津九年级化学题库

本地网页题库，按人教版九年级化学的单元和课题浏览、检索和组卷。在本机运行，无需登录。给家人用的。

简述一下这个东西是干嘛的，以及它目前是什么样子：主要是因为家人那边有需求，需要让 AI 改写部分题目拿给学生做。

现有的流程是：

1. 先把卷子差不多编好。
2. 把卷子丢给某一个 AI，让它找错别字或者做些基础处理。
3. 也有尝试过直接把整个文档丢给 AI，让它修改某些题目，让题面更灵活、对学生知识点的考察更全面。但效果不尽如人意，而且非常不灵活。

这里比较棘手的一点是它的格式是 Word。在编辑这方面，Word 作为富文本编辑器，确实比 Markdown 复杂不少。


## 如何运行

```bash
python3 -m venv venv
source venv/bin/activate
pip install python-docx lxml
python app.py serve
```

浏览器打开 http://127.0.0.1:8765 。

变式生成会从环境变量读取 `GLM_API_KEY` 和 `DEEPSEEK_API_KEY`。没有这两项时，浏览和组卷仍可使用。不要把密钥写进代码或提交到仓库。

## 不在本仓库中

题目数据库（`bank.sqlite`）和题目图片（`media/`）没有放进本仓库，需要在本机自行准备后再启动。

# 项目日志和吐槽

这个是 Grok bot做的，基本上干了一天，把 Weekly Usage 干没了 80%，实际就是到顶了。

之前用惯了 Codex 这种好东西，再去用 Grok bot，原来觉得没想到它在 coding 上也能用，但越用越发现出问题了：它完全不会去想边界条件。其实我一直觉得这个项目没那么复杂，只是要求繁琐了点：它自动分出来的类型不准，所以一定得给每一个题目都加上允许人工编辑类别、手工修改的能力。但 Grok 不像 Codex 能直接帮我把需要注意的东西提前想好，导致我必须跟它嘱咐极多事情。我非常不放心，之前强调过的东西，在后面的修改里我还得在旁边加个括号再重复一遍，反复跟它说“不要做某些事”。

比如一开始先拿了 20 个 doc 文件导入进来做测试，有些题目的分类和格式不行，我跟它反馈说这几个题目不好，题目分割没做对，类别判定也没做对，它就真的只改那几个题目。但我这边不是只有 20 个 doc，我有 500 多个 doc。我希望它是根据这些题目暴露出的问题去优化整个项目，方便后续所有文档使用，但它根本不听，完全不去想我到底要干什么，搞得人真的很累。

部署也是，我都不知道它是怎么想的。我让它部署到宿主机上，它居然没把 API key 放上去。我不问它自己都不知道，特地问了一遍，它才说“没给你放上去，现在给你放”。

还有一件事：因为是在国内使用，要配国内的模型，我第一个想到的就是 DeepSeek。昨天刚好开发测试能连通的一两个小时里，DeepSeek 那边的服务断了。Grok 就直接跟我说没有生成结果（不是我一定要吐槽一下，你这事跟 Codex 一说，人家自己去给我做测试去了，而不会直接告诉我“这个还没生成完”。就您这个 Grok 这边啊，您可等着吧！等半年之后，您这个 coding 能力或者说整体的 harness 能力追上那两家了？那哥们儿，你追不上，你追不上，你真追不上啊！给我气懵了），然后就停在那儿，根本不往下排查，也不告诉我是我程序有问题还是 API 提供方有问题。非得等我主动要求它去查原因，它才跟我说“DeepSeek 那边服务器是收到了，返回的状态码是 200，但没有后续输出”。

昨天跟 Grok 折腾这么一回，干没了我三倍的精力。我当时想的是，元数据那些 docx 不在我这台电脑上，在另外一台异地电脑里。既然它都把文件存到那台电脑上了，顺便直接在上面做开发、先跑完技术验证，最后再整体放到宿主机上，我就不用在自己电脑上再折腾一回。结果它就给我搞出这么个玩意儿。

经历这么一遭，我觉得我对它的定位从一开始就期望偏差了，直接把它当 Codex 用了。Grok 好像从一开始就不是给写代码、搞开发的人用的：很多东西它根本不思考，只管跑出一个结果就算完。至于中间怎么办、界面好不好用、能不能让没有技术背景的人一看就知道怎么操作，它完全不想。比如针对第一次使用、没有技术背景的人，界面起码要重点突出，或者一道题到底有没有被选中搞得醒目一点，哪怕你跟它说“搞醒目一点”，它都不会动；你必须给它极其 explicit 的指令：“选中了改成绿色底，没选中改成红色底”，说到这个份上它才会去改。

真的力竭了。
